公司現況與核心痛點

金屬扣件製造（螺絲生產）／使用 Google Workspace
痛點 1
訂單單位判斷問題（最複雜）
客戶訂單以 M 數（公尺）表示，但前段製程用 M 數、熱處理後段以重量計價；ERP 輸入時需「讀懂」文字描述才能判斷計價單位是「盒」還是「M 數」，每位客戶表達方式各異。
痛點 2
包裝階層計算問題
相同螺絲因客戶包裝要求不同，影響材積、出貨箱數與運費。階層包含：幾M→小包裝→中包裝→棧板，每層數量皆不同且寫在訂單文字描述中，格式不固定。
痛點 3
多子訂單拆分問題
客戶一次傳送大份訂單，內含多筆子訂單，各子訂單頁數與筆數不固定，無法用固定規則拆分，需人工逐頁判斷邊界後分別輸入 ERP。
痛點 4
客戶訂單格式完全不統一
每位客戶的訂單格式、欄位名稱、計量方式皆不同，任何依賴固定格式的自動化工具均無法適應。
🔍

問題本質診斷

為什麼一般自動化工具無法解決？
核心問題
非結構化資料的語意理解
訂單文字描述的「意思」需要被理解，而非僅複製特定位置的資料
❌ 傳統工具的能力邊界
  • 工作流程平台只能串接有 API 的系統，本身不懂語意
  • 簡單規則引擎只能處理預先定義好的條件分支
  • 任何依賴「固定格式、固定位置」的工具都無法適應
✅ 真正需要的技術組合
🧠 LLM（大型語言模型） → 讀懂語意、判斷單位與包裝結構
⚙️ 規則引擎 → 套用換算邏輯
👤 人工確認關卡 → 確保 AI 判斷正確後才進 ERP
🔗 ERP API / 批次匯入 → 執行最終資料輸入
💡 這類問題在業界稱為「非結構化訂單資料擷取」，是目前製造業 AI 導入最熱門的應用場景，線材業、紡織業、化工業皆有類似情境。

三大工具類別總覽

各類工具的核心定位與功能分工
🤖
RPA 工具
機器人流程自動化
代表：UiPath、Power Automate Desktop
核心能力：模擬人工操作畫面（點擊、鍵入）
適合：固定格式的重複性作業
🔗
工作流程自動化
Workflow Automation
代表：n8n、Make.com、Zapier
核心能力：串接不同系統的 API
適合：讓資料在系統之間自動流動
🧠
AI 軟體工具
Large Language Model
代表：Claude、ChatGPT、EgentHub
核心能力：語意理解、文字生成
適合：讀懂非結構化訂單描述
🔑 關鍵觀念：三者並非競爭關係，而是互補。單獨使用任何一種都無法解決扣件廠訂單處理的複雜性，需要組合運用。
🤖

RPA 工具優缺點分析

UiPath、Power Automate Desktop、Automation Anywhere

✅ 優點

  • 無需改動現有系統，直接操控畫面
  • 適合高重複性、格式固定的批次作業
  • 執行速度快、24 小時不間斷、錯誤率低
  • 提供錄製功能，降低技術門檻
  • 製造業導入案例成熟

❌ 缺點

  • 格式一改、位置一動，機器人即失效需重寫
  • 無法讀懂非結構化訂單文字的語意
  • 無法處理頁數不固定的多子訂單
  • 執行期間佔用桌面，同仁無法同時使用該電腦
  • 企業級授權費用高，整體維護成本持續累積
⚠️
重要限制：RPA 執行期間直接佔用桌面畫面（並非背景執行），同仁必須等待機器人跑完才能繼續工作。若要解決此問題，需另備「專用自動化電腦」，或購買伺服器版授權，額外增加成本。
💡 RPA 本質類似「自行撰寫的客製軟體」——格式一改就壞，壞了就要重寫，需持續投入維護，並非製造業的核心業務。

工作流程自動化平台分析

n8n、Make.com、Zapier 比較

✅ 優點

  • 串接 Gmail、Google Sheets、ERP API 等多系統
  • 視覺化拖拉介面，不需寫程式
  • 可整合 AI API，補強語意判斷能力
  • n8n 可自架，資料不出公司（資安友善）
  • 對 Google Workspace 整合完整
  • 成本低：n8n 自架幾乎零授權費

❌ 缺點

  • 需 ERP 開放 API，否則無法串接
  • 本身不具語意理解能力，需外接 AI
  • n8n 複雜流程需一定技術能力設定
  • Zapier 複雜流程按步驟計費，長期費用高

AI 軟體工具分析

Claude、ChatGPT、Gemini 及專業型 AI 應用

✅ 優點

  • 能讀懂非結構化訂單文字，判斷計價單位與包裝邏輯
  • 可處理中英文混合訂單，撰寫英文報價回覆
  • 只需調整提示詞（Prompt）即可應對不同格式
  • 可透過 API 嵌入 n8n，成為智慧判斷節點
  • 支援 MCP，可直接連接 Gmail、Google Sheets

❌ 缺點

  • 換工具後，之前「教 AI」的時間全部白費
  • 判斷不保證 100% 正確，必須有人工確認關卡
  • 資料送至雲端，需評估資安政策
  • AI 模型更迭快速，需評估切換成本
  • API 按 Token 計費，大量使用需控管費用
⚠️
隱性成本警示：讓 AI 理解公司業務邏輯（產品規格、客戶慣例、包裝計算）需大量時間投入。一旦更換 AI 工具，所有調教工作幾乎要從頭來過。建議同步建立「業務邏輯文件庫」，將 Prompt 範本、客戶訂單慣例表、例外案例等結構化記錄，降低換工具的重建成本。

建議不採用 RPA 的理由

提報管理層參考之建議方向
📌 建議結論：本次自動化導入規劃，建議不將 RPA 工具納入。
🔑 核心理由
01
類似自行撰寫的客製軟體
只要系統畫面格式改變、欄位位置調整，整個流程就會失效，需要重新修改撰寫，維護成本持續累積，並非一次建置即可長期使用。
02
執行期間同仁無法使用電腦
RPA 直接操控桌面畫面（非背景執行），執行期間螢幕被佔用，同仁無法同時工作。若需解決此問題，須另備專用電腦或購買高成本的伺服器版授權。
03
無法處理我們最核心的問題
RPA 對於「讀懂訂單文字描述」完全沒有能力，無法判斷語意、包裝階層，也無法處理頁數不固定的多子訂單。
🔄 RPA 原本負責的「ERP 資料輸入執行」部分，建議改以 ERP API 串接（優先）或 ERP 批次匯入功能（過渡方案）取代，既安全又無需額外維護負擔。

三階段導入路線圖

循序漸進，從最小可行方案開始
第一階段
1～2 個月
🤝 習慣 AI 協作
選定一款桌面 AI 工具（建議 Claude Code 或 OpenAI Codex），讓業務與行政人員用於整理訂單摘要、起草英文報價信、翻譯技術規格文件。不需任何系統串接，純人工輔助使用，先建立人機協作習慣。
第二階段
1～3 個月
🔗 串接 Google Workspace
建置 n8n（建議自架）。設計 Gmail → n8n → AI → Google Sheets 流程：Gmail 收到訂單→ n8n 取出內容 → AI 解析 → 結果寫入 Google Sheets 供人員確認。確認正確後，人工進行 ERP 輸入。
第三階段
3～6 個月
⚙️ 連接 ERP 自動輸入
優先評估 ERP 是否有 API 可串接；若無，採用批次匯入（Excel/CSV）作為過渡方案；中長期可評估請 ERP 廠商開發客製介面模組。加入例外處理機制，AI 不確定時自動轉人工。
🎯 關鍵原則：先從「最痛的一個流程」開始，做出成果讓團隊感受到效益，後續推廣才有動力。不要試圖一次自動化所有流程。

AI 導入核心策略

三大策略原則，確保長期效益
🏆
策略一：選定平台架構，深度熟練，不輕易追新
AI 工具日新月異，若一直追求最新工具，團隊永遠處於「重新適應」的狀態。真正的資產不是工具本身，而是：公司流程的 AI 化程度、團隊的人機協作熟練度、累積的 Prompt 設計知識，以及業務邏輯的文件化程度。
📚
策略二：業務邏輯必須文件化，避免重複訓練 AI
讓 AI 理解公司業務需大量時間投入。若這些知識只存在於「AI 對話記憶」中，換工具就全部白費。應建立「AI 業務邏輯文件庫」：產品規格對照表、客戶訂單慣例表、Prompt 範本庫、例外案例記錄，降低換工具的重建成本。
🔌
策略三：採用 MCP 架構，降低對單一廠商依賴
MCP（Model Context Protocol）是 Anthropic 推出的開放標準，OpenAI、Google 等已跟進，正成為 AI 串接工具的通用介面。透過 MCP，AI 可直接連接 Gmail、Google Sheets 等工具。關鍵優勢：底層換 AI 模型時，MCP 串接架構不需重做。
🔌

ERP 串接方式選擇

依 ERP 廠商支援狀況選擇最適方案
✅ 方式一：API 串接（最推薦）
若 ERP 廠商提供 REST API 或 Web Service，n8n 可直接呼叫。資料走 ERP 應用層，驗證邏輯、庫存計算、審計記錄正常運作。→ 優先向 ERP 廠商確認是否提供 API 文件。
🔄 方式二：批次匯入 Excel/CSV（過渡方案）
幾乎所有 ERP 都提供批次匯入功能。n8n 將 AI 解析好的訂單資料自動產生成符合格式的 Excel，人工或自動觸發匯入。走官方介面，ERP 業務邏輯正常運作，技術門檻低。→ 無 API 時立即可用的最安全方案。
🔧 方式三：ERP 廠商客製介面模組（中長期）
委託 ERP 廠商開發輕量 API 或匯入介面。由原廠開發，資料完整性有保障，可客製化欄位與邏輯。需額外費用與開發時間。→ 適合列為中長期目標。
🚫 方式四：直接寫入 SQL（不建議）
繞過 ERP 應用邏輯，可能造成庫存不一致、審計記錄缺失；ERP 廠商通常不允許此方式，出問題後不提供技術支援。與 RPA 一樣，ERP 升級後寫入腳本也需重新修改。→ 除非廠商明確提供保障，否則不應採用。

結論與後續行動

建議方向總結

📌 核心建議

以「n8n（系統串接）+ Claude/GPT（語意判斷）+ 人工確認」為核心架構，分三階段逐步導入。選定平台後深度熟練，同步建立業務邏輯文件庫，採用 MCP 架構降低廠商依賴，確保長期可持續發展。

1向 ERP 廠商確認 API 支援狀況及批次匯入格式文件
2選定桌面 AI 工具（Claude Code 或 OpenAI Codex），讓業務人員開始使用
3建立螺絲規格單位換算對照表及客戶訂單慣例表
4評估 n8n 自架可行性（資訊部門或委外協助）
5選定第一個試點流程（建議從訂單摘要自動整理開始）
6建立「AI 業務邏輯文件庫」，記錄 Prompt 範本與例外案例
